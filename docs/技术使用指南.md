## 1 系统架构

### 1.1 模块全景

```
┌────────────────────────────────────────────────────────────────────┐
│                        embed_harness.py (主编排器)                  │
│   一轮循环 = 编译 → 烧录 → 监控 → 断言 → AI 分析 → 修改 → 再验证      │
└───────┬───────────┬──────────────┬───────────────┬────────────────┘
        │           │              │               │
   BuildSystem    monitor       expectations    ai_backend / feedback
   编译+烧录       采样客户端      断言引擎          AI 决策
   (OTA 双区)     (OpenOCD/      (8 种检查)        (4 个工具 + 子代理)
                  Renode/Hybrid)
        │           │              │               │
        └───────────┴──────┬───────┴───────────────┘
                           │
                  policy.py (策略门控) ── memory.py (分层记忆)
                  文件白名单/内容安全/ELF      短期JSONL + 长期SQLite
```

### 1.2 一轮迭代的生命周期

`AIEmbedHarness.execute_one_iteration()`（[embed_harness.py:415](embed_harness.py#L415)）：

| 阶段 | 动作 | 失败处理 |
|------|------|---------|
| ① 编译 | `BuildSystem.build()`（`--skip-build` 时跳过） | 编译失败 → 记录错误，返回本轮 |
| ② 烧录 | `BuildSystem.flash()`，OTA 模式烧 4 段 | 硬件性失败（`fatal`）→ `sys.exit(1)` 停止迭代 |
| ③ 监控 | `monitor.sample_multiple()` 并行采样所有变量 | 无数据 → 提示检查 OpenOCD / 变量名 |
| ④ 断言 | `run_checks()` 对每项 expectation 判 pass/fail | — |
| ⑤ 记录 | `memory.record()` + `history.append()` | — |

`--monitor-only` 跳过 ①②，`--skip-build` 跳过 ①——两者都只依赖已有的 OpenOCD 进程与 ELF。

### 1.3 三种硬件后端

| 后端 | 传输层 | 适用场景 | 说明 |
|------|--------|---------|------|
| `swd` | OpenOCD TCL (127.0.0.1:6666) | 真硬件 | 读写芯片寄存器/内存，最常用 |
| `renode` | Renode TCP (12347) | 全仿真 | LCD 可读像素，跑得快但需预热 |
| `hybrid` | 双后端自动路由 | 复杂系统 | LCD 走 Renode，CAN 走 SWD，三级熔断 |

后端统一通过 `create_backend(name, project_dir, elf_path)`（[embed_harness.py:59](embed_harness.py#L59)）创建；Hybrid 后端实现 `sample_multiple()` 与 `mode_info`，与 SWD 后端接口对齐，上层无感切换。

### 1.4 关键配置点：`HarnessConfig`

[embed_harness.py:117](embed_harness.py#L117) 是每项工程的适配层，需要按你的实际环境修改：

```python
class HarnessConfig:
    OPENOCD_HOST = "127.0.0.1"
    OPENOCD_TCL_PORT = 6666
    ST_SCRIPTS    = "E:/ST/.../st_scripts"       # CubeIDE 自带 OpenOCD 脚本目录
    OPENOCD_EXE   = "E:/ST/.../openocd.exe"      # 绝对路径
    GDB_CMD       = "arm-none-eabi-gdb"
    SAMPLE_INTERVAL = 0.3    # 秒，采样间隔
    SAMPLE_DURATION = 3.0    # 秒，单轮采样时长
    BOOT_WAIT        = 1.5   # 烧录后等待芯片启动
    MONITOR_SCRIPT   = "E:/.../stm32_monitor.py" # 备用 MonitorScriptClient 脚本
```

> **Windows 路径注意**：OpenOCD 与 GDB 不认反斜杠（`\b` 会被解析成退格符）。`BuildSystem` 内部通过 `Path.as_posix()` 把所有路径转成 `/`。

## 2 硬件后端原理

### 2.1 SWD 后端（OpenOCDClient）

[monitor_client.py:23](monitor_client.py#L23)，核心是 TCL 通道：

- **连接**：TCP 连 `127.0.0.1:6666`（OpenOCD 的 TCL 端口）。由 CubeIDE 调试会话启动，或独立启动。
- **命令原语**：`_tcl_send(cmd)` 发送一条 TCL 命令并读回。
- **地址解析**：`resolve_address(elf_path, expression)` 用 GDB 把符号（如 `GPIOA_ODR`、`g_can_sensor.temperature`）解析成内存地址——支持结构体字段、数组下标等 GDB 表达式。
- **读写原语**：
  - `read_memory(addr, width=8|16|32, count)` — 指定位宽读内存
  - `write_memory(addr, value, width)` — 指定位宽写内存
  - `read_variable(elf_path, expr)` / `sample_variable` — 符号级采样
- **外设寄存器**：`read_register(svd_path, peripheral, ...)` 支持 SVD 文件按外设/寄存器名读取。

`sample_multiple()` 返回的数据结构（断言引擎与 AI 报告的输入）：

```python
# {变量名: [{"timestamp": float, "value": int|float, "raw": ...}, ...]}
samples = {
    "GPIOA_ODR": [{"timestamp": 1720.1, "value": 0x4000}, ...],
    "g_can_sensor.temperature": [...],
}
```

### 2.2 Renode 模拟器后端

`renode/` 目录提供 LCD 外设模型（`NT35510.cs`，源码编译出 `.dll` 供 Renode 加载）。虚拟变量以 `_` 前缀命名，如 `_lcd_active_pixels`、`_lcd_screen_updated`，由 Renode 追踪器输出，供断言引擎直接消费。适合无硬件时的回归测试，仿真速度慢需预热。

### 2.3 Hybrid 混合后端与三级熔断

[hybrid_backend.py:129](hybrid_backend.py#L129) `HybridBackend` 对变量按来源自动路由（LCD 变量走 Renode，CAN 变量走 SWD），通过 `_update_mode()` 维护当前模式。每一层依赖由 `CircuitBreaker` 保护：

| 熔断器 | 阈值 | 冷却时间 | 保护对象 |
|--------|:----:|:-------:|---------|
| Renode | 3 次失败 | 30s | LCD 仿真读取 |
| SWD | 5 次失败 | 60s | 真硬件读取 |
| Hybrid 全链路 | 10 次失败 | 120s | 整条采样链路 |

模式自动降级路径：`hybrid → renode_only / swd_only → degraded → 自动恢复`（`_update_mode()` 实现）。任何一次 `sample_multiple()` 失败不会抛异常，而是落到降级分支，保证主循环不中断。

## 3 场景定义（YAML Schema）

场景文件是 Harness 的"任务书"。加载流程：`load_scenario()` → `scenario_to_harness()`（[embed_harness.py:1139](embed_harness.py#L1139)）→ 得到 `(variables, expectations)`。

### 3.1 顶层结构

```yaml
name: "场景名称"               # 用作 scenario_desc 与 AI 目标描述
description: "一句话描述"       # 无 name 时兜底
targets:                       # 监控 + 断言列表（核心）
source_files:                  # AI 允许修改的文件白名单（空 = 纯监控）
expected_waveform: "..."       # 可选，期望波形的人类描述
notes: |                       # 可选，前置条件 / 已知限制
```

### 3.2 `targets` 语法

每个 target 定义一条监控+断言：

```yaml
- variable: "g_can_sensor.temperature"   # GDB 符号表达式（支持结构体字段 / 数组下标）
  check: range                           # 断言类型
  width: 8                               # 可选，读取位宽 8/16/32（默认按符号推断）
  type: float                            # 可选，IEEE754 32-bit 原始值 → Python float
  params:                                # 断言参数（见 3.3）
    min: 10.0
    max: 50.0
```

同一变量可声明多条 target（如 `frequency` + `change_detected`），重复变量自动去重为一次采样。

**变量表达式能力**：
- 结构体字段：`g_can_sensor.valid`、`CAN_RxMsg.Data[0]`
- 寄存器符号：`GPIOA_ODR`（可做 `frequency` 检查）
- Renode 虚拟变量：`_lcd_active_pixels`（仅 hybrid/renode 后端可用）

### 3.3 断言类型索引（`check` + `params`）

| check | params | 判定 |
|-------|--------|------|
| `monotonic` | `direction: increasing/decreasing/strict_increasing/strict_decreasing` | 序列单调性 |
| `range` | `min`, `max` | 所有样本落在 `[min, max]` |
| `frequency` | `target_hz`, `tolerance`(默认 0.1) | 翻转频率误差 < tolerance |
| `rate` | `target_min`, `target_max` | 单位时间增量在区间内 |
| `change_detected` | — | 观察期内发生过变化 |
| `pattern` | `expected: [...]` | 序列匹配（前 N 个，≥80% 模糊） |
| `state_machine` | `expected_states: [...]` | 状态跳转顺序匹配 |
| `stable_after` | `threshold`(默认 0.05), `min_stable_samples`(默认 3) | 后半段稳态误差 < threshold |

### 3.4 `source_files` 白名单语义

非空时，AI 只能修改列表内的文件（相对工程根）。列表为空 `[]` = **纯监控**，AI 被禁止任何文件修改——这是 `full_monitor.yaml` 和 `my_ota_can.yaml` 的用法。

### 3.5 实战场景剖析

**`led_blink.yaml`** — 频率调优闭环：
```yaml
targets:
  - variable: "GPIOA_ODR"
    check: frequency
    params: { target_hz: 2.0, tolerance: 0.15 }  # 2Hz ±15%
  - variable: "GPIOA_ODR"
    check: change_detected
source_files: ["Core/Src/main.c", "Core/Src/gpio.c"]  # AI 只许改延时/定时器
```
失败信号 → AI 对照"frequency 不达标 → 调整 HAL_Delay 或定时器 PSC/ARR"根因表修改 → 再烧再测。

**`my_ota_can.yaml`** — F103→F407 CAN 链路监控：
- `g_can_sensor.valid == 1`（收到至少一帧）、`tick` 单调递增、`temperature/humidity` 在合理区间
- `source_files: []` → 纯监控，F407 固件不可改
- `notes` 里写清硬件前置：PA11=RX, PA12=TX, 500kbps, F103 发 ID=0x12 帧

## 4 断言引擎算法详解

[expectations.py](expectations.py) — 将原始采样转成结构化 pass/fail，供 AI 直接消费。

### 4.1 数据预处理（`run_checks`，[expectations.py:264](expectations.py#L264)）

每个样本先归一化：
- 默认：值直接 `float()` 转换（十六进制字符串 `0x...` 先转 int）。
- `type: float`：原始 int 按**小端**打包成 4 字节，再 `struct.unpack("<f", ...)` 解成 IEEE754 浮点——用于 CAN 传感器温度/湿度等 `float` 全局变量。

### 4.2 各检查算法

**`frequency`**（LED/PWM）：统计相邻样本数值变化次数 `transitions`，以两次跳变（上升+下降）= 一个完整周期：
```
实际频率 = transitions / (2 × 总时长)，总时长 = 样本数 × 采样间隔
判定：|实际 − target| / target < tolerance
```
> ⚠️ 采样间隔不足一个周期的一半时会严重低估频率（奈奎斯特）。`bate_camera.yaml` 中对 `ov_sta`（~33ms 周期）明确提示需 <10ms 采样。

**`rate`**（帧率/计数增速）：
```
变化率 = (末值 − 首值) / 总时长
```

**`stable_after`**（PID 收敛）：
```
取后半段 tail，均值 avg，最大偏差 max_dev = max(|v − avg|)
判定：max_dev < threshold，且样本数 ≥ 2 × min_stable_samples
```

**`monotonic`**：遍历比较相邻样本；支持严格/非严格、递增/递减。

**`change_detected`**：任意样本 ≠ 首样本即通过。**注意**：值从未变化可能意味着外设未初始化，而非状态正常。

**`state_machine`**：先去重相邻重复值得到实际状态序列（`[1,1,2,2,3]` → `[1,2,3]`），再与前缀匹配，要求**完整走完**期望序列。

**`pattern`**：前 N 个样本与期望逐位比较，`≥80%` 模糊匹配也通过。

**`range`**：全部样本都在 `[min, max]` 内（任一越界即失败），detail 中会报告越界点数。

### 4.3 结果对象

`CheckResult(passed, var, detail, actual, expected)`，`detail` 是给 AI 的中文描述（如 `[FAIL] 目标 2Hz，实际 1.13Hz（9 次跳变 / 4.0s），误差 43.5% > 容忍 15%`），可直接喂给大模型。

## 5 AI 决策后端

[ai_backend.py](ai_backend.py) — `ClaudeAIBackend.decide(obs, scenario_desc) → AIDecision`。

### 5.1 工具集（按代理层级裁剪）

| 工具 | 主模型(depth=0) | 子代理(depth=1) | 作用 |
|------|:---:|:---:|------|
| `submit_decision` | ✅ | — | 提交最终决策：`goal_achieved` + `code_changes[]`（file/description/content 完整新内容） |
| `delegate_sub_agent` | ✅ | — | 将 ≥3 文件或跨模块修改拆分给子代理并行执行 |
| `navigate_page` | ✅ | — | 翻页 + 跳转后监控指定变量（SWD） |
| `knob_action` | ✅ | — | 模拟旋钮：rotate_left/rotate_right/press |
| `output_file` | — | ✅ | 子代理唯一工具，输出单个文件的完整内容 |

工具裁剪逻辑见 `tools` 属性（[ai_backend.py:377](ai_backend.py#L377)）：子代理看不到 `delegate`/`navigate`/`knob`，实现**隔离**，防止越权操作。

### 5.2 子代理机制

```
主模型 (depth=0)  分析反馈 → 需要改 N 个文件
   └─ delegate_sub_agent(tasks=[{file, instructions}×N])
        └─ 每个子代理 (depth=1) 只编辑 1 个文件，输出完整新内容
主模型收集子结果 → 汇总 → submit_decision(code_changes)
```

子代理系统提示词强制：**只改指定文件的指定内容、输出完整文件、不新增功能、不再委派**。

### 5.3 系统提示词设计要点

- **目标导向**：所有断言通过 → `goal_achieved=true`，禁止画蛇添足优化。
- **信号驱动**：断言失败是明确的硬件信号，针对性修改。
- **换向策略**：同一条断言连续失败 → 判定先前方向错误，换方案。
- **内置根因对照表**（频率→延时/分频、range→限幅、change_detected→时钟/中断、monotonic→缓冲、stable_after→PID 参数），大幅减少盲目修改。

### 5.4 AI 收到的反馈格式（`Observation.to_ai_prompt`）

[feedback.py:107](feedback.py#L107) 生成的报告分五段：
```
【硬件反馈】第 N 轮
目标: <scenario_desc>
状态: [OK]编译 | [OK]烧录 | 3/5 通过 | <memory_context>
── 编译 ──
── 断言检查 (3/5 通过) ──
  [FAIL] 目标 2Hz，实际 1.13Hz ...
── 采样 ──
  GPIOA_ODR: [0x2000 ~ 0x4000] 平均 ... (20 个样本)
```
`compact` 模式下用 `TokenBudget.compress()` 压缩长文本（记忆/日志段），断言 detail 永远**全文保留**——它是 AI 决策的核心依据。

## 6 SWD 模拟人工操作

原理详见 [AI模拟人工操作硬件原理.md](AI模拟人工操作硬件原理.md)。此处给出 `SWDInputSimulator`（[monitor_client.py:223](monitor_client.py#L223)）的实现要点。

### 6.1 函数调用协议：`halt → resume [map_addr]`

[monitor_client.py:315](monitor_client.py#L315) `call_func()`：

```
无参: halt → resume [link_address] → sleep(N)
有参: halt → reg r0 val → reg r1 val → ... → resume [link_address] → sleep(N)
校验: halt → reg pc（HardFault 检测）→ resume
```

硬性规则（实机验证）：
- **必须用 `resume [map_addr]`**，`reg pc + resume` 会 HardFault——`resume` 命令忽略 `reg pc` 的修改。
- `link_address` 取 `.map` 文件地址**不加 1**，`resume` 自动设 Thumb 位。
- `resume` 保留原 LR，函数返回自动回到 RTOS 上下文，**无需手动设 LR**。
- **页面函数**（`mode/settings/clock/camera` 的 show/hide）调用后**不可 `halt`**——halt 会冻住 LVGL 的 Systick 定时器导致动画卡死，跳过 HardFault 检查直接返回。
- **非页面函数** 调用后 `halt` 检查 `reg pc`，命中 `HardFault` 判失败。

### 6.2 页面切换：`switch_page`

```
子页只能从主页进入：
  main → 子页A → main → 子页B → main（子页间直跳 → LVGL 资源冲突 → 卡死）
返回主页 = 调当前子页的 xxx_ui_hide 函数
切换后 sleep(5s) 等 LVGL 渲染 + SPI Flash 读图 + FADE_IN 200ms 动画
```

内部维护 `_current_page` 状态，若当前在子页却要进另一子页，**先自动回主页**。

### 6.3 触摸 / 旋钮 / 主题 / OTA

| 操作 | 实现 |
|------|------|
| `touch_press(x, y)` | 写 `g_last_x`(16) `g_last_y`(16) `g_pressed=1`(8) |
| `touch_release()` | 写 `g_pressed=0`(8) |
| `touch_click(x, y)` | press → 100ms → release → 200ms → `touch_poll()` 让 LVGL 处理事件 |
| `set_theme(id)` | 写 `g_theme_id`(8) → `settings_ui_show`（0暗黑/1明亮/2护眼） |
| `trigger_ota()` | 写 `g_ota_pending=1`(8) |

这些是内存变量直写，非函数调用，速度快且不打断 CPU。

### 6.4 变量读写与地址

`read_var(name, width)` / `write_var(name, value, width)` 基于 GDB 符号解析 + `mdb/mwb/mwh` 位宽命令。地址可预先解析缓存（`_var_addr`），避免每轮重复符号解析。

## 7 策略门控

[policy.py:151](policy.py#L151) `PolicyGateway`，AI 每次 `submit_decision` 前强制校验，任何一环不通过即拒绝该文件修改：

| 检查 | 说明 |
|------|------|
| `check_file_whitelist` | 按场景匹配 `PolicyRules.FILE_WHITELIST`，未匹配时用 `DEFAULT_WHITELIST`；越界文件直接拒绝 |
| `check_content_safety` | 正则扫描新内容，拦截 `RCC`/`Flash`/`NVIC` 等危险寄存器操作模式 |
| `check_elf_symbols` | 编译后校验 ELF 中关键符号（防止 AI 改掉函数签名/删关键定义） |
| `has_repeated_violations` | 连续违规计数 → 熔断 AI 的修改权 |
| `get_audit_summary` | 输出审计日志，便于事后追溯"谁改了哪个文件" |

配合 `TokenBudget`，被拒绝的修改会作为反馈回灌给 AI，引导其换方案。

## 8 分层记忆

[memory.py:278](memory.py#L278) `HarnessMemory`，为 AI 提供跨轮/跨场景经验：

| 层 | 存储 | 机制 | 用途 |
|----|------|------|------|
| 短期 | JSONL，按天分片 | `query_recent(hours=2)` 取最近 2 小时 | 最近几轮反馈上下文 |
| 长期 | SQLite | `query_similar(scenario, limit=5)` 按场景相似度检索 | 跨场景模式复用（上次同类问题怎么解的） |

`build_context(scenario)` 聚合两层记忆注入 AI 提示词；`record_decision()` 记录 AI 的决策与结果，形成"做了什么 → 结果如何"的学习闭环。

## 11 踩坑记录与最佳实践

（以下均来自实机验证，改动前先读一遍）

1. **函数调用必须 `resume [map_addr]`，禁止 `reg pc + resume`** → 会 HardFault。
2. **页面切换必须经过主页**：`main → 子页A → main → 子页B`，子页间直跳卡死。
3. **LVGL 渲染不能被 halt 打断**：页面函数调用后不可 halt（冻结 Systick 动画定时器）；`resume → sleep(5s)` 让 LVGL 自由渲染。
4. **Windows 路径反斜杠**：OpenOCD/GDB 把 `\b` 当退格符，所有路径必须 `Path.as_posix()` 转 `/`。
5. **Windows 终端 GBK 编码**：Rich 输出的 emoji 在 GBK 终端崩溃，输出用 ASCII-safe 字符，stdout 包装 `errors='replace'`。
6. **CAN 变量会被硬件覆盖**：`g_can_sensor` 由 F103 以 50Hz 写，SWD 本地写 `knob`/`key_event` 会被下一帧覆盖——**页面导航不能用变量写，必须用函数调用**。
7. **`frequency` 检查注意采样率**：采样间隔 ≥ 周期一半会低估频率，需按信号周期选 `--interval`。
8. **`--monitor-only` 调试利器**：改完代码 → 在 CubeIDE 里点烧录 → 直接 `--monitor-only --skip-build` 采样验证，不必每次跑完整编译烧录闭环。
9. **熔断不是错误**：Hybrid 中 Renode 掉线会触发熔断降级到 `swd_only`，属正常保护，不要当 bug。
10. **float 变量必须声明 `type: float`**：否则 32 位原始值会被当 int 比较，断言必然错误。
