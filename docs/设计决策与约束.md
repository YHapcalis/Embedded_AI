## 2. 设计决策记录（问题 → 结论）

| # | 当初的问题 | 结论 | 落点 |
|---|-----------|------|------|
| P1 | SWD 能否覆盖主流 MCU？ | 只覆盖 ARM，会错过 ESP32/RISC-V | 双协议设计，transport 由 Profile 决定底层 openocd.cfg |
| P2 | 是否预封装 JTAG？ | 必须，双协议接口不变 | session/flasher 均协议无关 |
| P3 | CubeIDE 内置 OpenOCD 换芯片能用？ | 不能，scripts 不通用，需多分支共存 | `openocd_registry.py` 扫描注册 + `script_dir` 注入 `-s` |
| P4 | VSCode 定制 STM32 换芯片怎么办？ | 板卡 Profile + 自动生成配置 | `boards/*/profile.json` + `vscode_gen.py` |

> 补充（2026-08-29 真机复现验收时确立）：
> - **冷启动必须注入 `-s`**：ST 分支 OpenOCD 的 scripts 库在
>   `mcu.debug.openocd` 插件的 `resources/openocd/st_scripts/`，
>   靠 Registry 的 `script_dir` 字段解析
> - **诊断前必须冻结看门狗**：板上固件 IWDG 运行中，fault 后 CPU
>   停止喂狗，IWDG 会在"fault → 诊断"窗口内复位芯片清空 CFSR
>   （详见 `验收记录_S1-S10.md` 复现附录）
> - **确定性故障复现姿势**：在 `HardFault_Handler` 入口下硬件断点，
>   fault 即 halt，现场永久保鲜
