# 程序挂死 / 跑飞诊断

> 来源：改编自 AixProbe 技能包（CC BY-NC-SA 4.0，非商用）
> 适配：foundation 工具接口（MCP 风格）

## 适用场景

- 设备不响应但没有明确崩溃
- 串口无输出或持续重复某行
- LED 停止闪烁
- 程序运行一段时间后某功能不工作
- 看门狗反复复位

## 核心策略：多次采样 PC

程序挂死本质是**死循环**或**死锁**。通过多次 halt-读PC-resume，看 PC 分布来判断。

## 第 1 步：PC 采样（5 次）

```
→ connect()
→ halt()
→ register_read("pc")    // pc_1
→ resume()

→ halt()
→ register_read("pc")    // pc_2
→ resume()

... (共 5 次采样)

→ halt()
→ register_read("pc")    // pc_5（最后一次保持 halt 供分析）
```

## 第 2 步：分析 PC 分布

### 情况 A：所有 PC 集中在同一地址附近（±几十字节）

**诊断：死循环**

程序卡在一个循环里，等待某个条件永远不成立。

```
→ register_read("all")
```

常见死循环模式：
- `while(FLAG==0)` — 等待中断设标志，但中断未触发
- 忙等外设就绪 — 外设时钟未开或配置错误
- `while(1){}` — 误入空循环

### 情况 B：PC 在两个地址间交替

**诊断：两个函数互相调用 或 中断处理循环**

检查 xpsr 看是否在中断中：
```
→ register_read("xpsr")
```
异常号非 0 说明在中断处理，可能是中断不断触发。

### 情况 C：PC 每次都不同且分散在 Flash 范围

**诊断：程序在正常运行**

问题可能不是挂死，而是：
- 特定功能路径未执行到
- 通信协议层问题
- 外设配置错误导致无输出

→ 转到外设诊断（见 SKILL.md 路由表）

### 情况 D：PC 不在合法地址范围

**诊断：程序跑飞**

参考 chip-reference.md 确认 Flash/SRAM 范围。PC 在非法区域说明：
- 栈溢出覆盖了返回地址
- 函数指针被破坏（野指针）
- 中断向量表损坏

检查栈溢出：
```
→ register_read("sp")
// SP 接近 SRAM 起始地址 = 栈溢出
```

检查向量表：
```
→ memory_read(0x08000000, 16)   // 向量表通常在 Flash 起始
// 偏移 0x00 = 初始 SP（应指向 SRAM 末尾）
// 偏移 0x04 = Reset_Handler（应在 Flash 范围）
```

## 第 3 步：死锁检测（RTOS 场景）

如果目标运行 FreeRTOS/RT-Thread 等 RTOS：

```
// 读当前任务 TCB（FreeRTOS: pxCurrentTCB 是全局变量）
// 地址需要从 ELF/map 文件获取
```

死锁表现：多个任务都阻塞在信号量/互斥锁上。

## 第 4 步：检查复位原因

设备反复复位时，读复位状态寄存器：

**STM32 RCC_CSR（F4 系列 @ 0x40023C74）：**

| 位 | 名称 | 含义 |
|----|------|------|
| [26] | LPWRRSTF | 低功耗复位 |
| [27] | WWDGRSTF | 窗口看门狗复位 |
| [28] | IWDGRSTF | 独立看门狗复位 |
| [29] | SFTRSTF | 软件复位 |
| [30] | PORRSTF | 上电复位 |
| [31] | PINRSTF | 引脚复位（NRST） |

> IWDGRSTF=1 → 看门狗超时，说明程序卡死超过看门狗周期

## 第 5 步：中断状态检查

怀疑中断风暴时：

```
// NVIC 中断活跃寄存器 IABR0-7
→ memory_read(0xE000E300, 8)

// NVIC 中断挂起寄存器 ISPR0-7
→ memory_read(0xE000E200, 8)

// NVIC 中断使能寄存器 ISER0-7
→ memory_read(0xE000E100, 8)
```

活跃位=1 的中断正在执行；挂起位=1 的中断等待执行。
